# Survival analysis

This module tests ALD/DLD and true AMP/DEL associations with overall survival across TCGA cohorts. The primary screen uses log-rank tests. The LGG follow-up fits unadjusted and IDH/grade-adjusted Cox models to significant ALD/DLD log-rank hits.

## Inputs and run order

Run scripts from the Workflow project root. Run the core workflow first with the desired `config.R` settings; survival scripts read its prepared expression/CNV data, gene lists, and ALD/DLD calls. Clinical OS data are retrieved through TCGAbiolinks and cached per cohort. OS uses days to death for deceased patients and days to last contact/follow-up for censored patients; the event indicator is 1 for death and 0 for censoring.

1. Run `analysis/survival/scripts/logrank/run_logrank_survival_screen.R`.
2. Run `analysis/survival/scripts/logrank/make_significant_logrank_survival_table.R`.
3. Run `analysis/idh/run_IDH_LGG_ALD_DLD_analysis.R` to produce the patient-level IDH labels, then run `analysis/survival/scripts/logrank/run_LGG_adjusted_cox_followup_for_logrank_hits.R`. IDH-mutant labels are assigned from TCGA somatic mutation records carrying IDH1 R132 or IDH2 R172 hotspot mutations; other patients in the IDH analysis sample set are labeled IDH-wildtype. These labels are saved in the per-sample CSV under `analysis/outputs/idh`. The Cox follow-up reads only patient identifiers and IDH labels from that file for covariate adjustment; IDH labels are not inferred from burden comparisons or enrichment-test results.

The four primary comparisons are ALD versus other diploids, DLD versus other diploids, AMP versus diploids excluding ALD, and DEL versus diploids excluding DLD. Tests require ten patients per group after OS matching. Benjamini-Hochberg FDR is applied separately within each cohort/comparison; summaries are generated at FDR 0.05 and 0.10. Direction uses observed minus expected events in the tested group: positive means worse survival, negative means better survival.

## ALD amplified-expression filter

When `ald_min_amplified_median_tpm` is enabled in `config.R`, survival reads the corresponding `aldTPMgt<value>` core subfolder. ALD screens use `ald_eligible_genes.rds`; true AMP screens retain `amplified_genes.rds`. Only the filtered ALD calls are excluded from the AMP diploid reference, so genes failing ALD eligibility can still be tested for true amplification. DLD/DEL definitions and clinical OS caches are unchanged. Survival tests use patient counts after OS matching, not an amplified-gene burden denominator.

Filtered log-rank and Cox results are isolated beneath an `aldTPMgt<value>` output subfolder and have the same tag in their filenames. `NULL` preserves baseline input/output paths and names. The significant-hit table and LGG Cox follow-up read the matching log-rank outputs; Cox reads the matching TPM-tagged IDH per-sample file.

The AMP follow-ups require a matching TPM-tagged Table 12 with `ald_tpm_filter_enabled`, `ald_min_amplified_median_tpm`, and `ald_tpm_tag` in its Settings sheet; they will not fall back to the baseline table.

For LGG log-rank-significant ALD/DLD genes, Cox models include unadjusted, IDH-adjusted, grade-adjusted, and IDH-and-grade-adjusted models. Models require ten patients per group and ten death events after matching and applicable covariate filtering. Cox p-values are corrected separately within each model/state.

Repeat the log-rank screen and significant-table builder with the core `genes_in_peak` setting and corresponding core outputs for peak-restricted sensitivity results. Results are stored separately from default wide-peak results.

## Additional follow-ups

- `run_logrank_reference_group_sensitivity.R` compares AMP excluding ALD, AMP including ALD in the diploid reference, and AMP+ALD versus remaining diploids. It requires existing default AMP log-rank outputs and Supplementary Table 12, generated by the Figure 7 builder, for the original significant AMP directions. Generate Table 12 before running this follow-up. Its workbook contains cohort summaries and gene-level comparisons of these three definitions.
- `run_ALD_AMP_HR_concordance.R` reads significant ALD cohort-gene pairs and original directions from Supplementary Table 12, generated by the Figure 7 builder. It tests AMP versus diploids excluding ALD and calculates `(O_AMP/E_AMP)/(O_reference/E_reference)`. This observed-to-expected event-ratio estimate is not a Cox-model HR. Thresholds 1.1, 1.2, 1.5, and 2.0 use reciprocal lower bounds. Generate Table 12 before running this follow-up.

Both follow-up scripts are in `analysis/survival/scripts/logrank/` relative to the Workflow root and require the default `wide_peak` GISTIC setting. The Figure 7 builder also requires the LGG Cox follow-up outputs and the `genes_in_peak` significant-hit table; generate those inputs before building Table 12.

## Directory structure

Paths below are relative to `analysis/survival/`. `<aldTPMtag>` is `aldTPMgt1` for the default >1 TPM requirement; omit that directory level when the requirement is disabled.

- `R/`: shared preparation and statistical helpers.
- `scripts/logrank/`: primary screen, significant-table builder, LGG Cox follow-up, and AMP checks.
- `outputs/logrank/<aldTPMtag>/<cohort>/`: per-cohort primary results.
- `outputs/logrank/<aldTPMtag>/fdr_<threshold>/`: summaries and significant-hit tables.
- `outputs/logrank/genes_in_peak_version/<aldTPMtag>/`: peak-restricted results.
- `outputs/logrank/<aldTPMtag>/AMP_reference_group_sensitivity/`: workbook used by Supplementary Table 15.
- `outputs/logrank/<aldTPMtag>/ALD_AMP_HR_concordance/`: workbook used by Supplementary Table 16.
- `outputs/cox/<aldTPMtag>/LGG/adjusted_followup_logrank_hits/`: Cox results used by Figure 7B and Supplementary Table 13.
- `cache/`: processed clinical OS inputs.
- `GDCdata/`: downloaded clinical data.

Scripts/helpers create output, cache, and download directories when needed. Cached OS endpoints are reused unless explicitly rebuilt. Generated results and downloaded data are distinct from the code required for reproduction.
